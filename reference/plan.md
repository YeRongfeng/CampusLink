# CampusLink Framework V1 实施计划

## 目标与已确认选择

建立可运行、视觉统一、便于三人独立开发的公共框架，覆盖认证、首页、个人中心、文件上传及业务占位页。

- 从现有空工程开始，保留草稿和已有文件修改。
- 使用草稿指定技术栈，本机 MySQL，不使用 Docker。
- 首页和三个模块首页公开；个人中心及“我的内容”需要登录。
- 采用浅色背景、清新绿色主色的校园生活风格。
- 分四轮实施，每轮提交验收结果，用户检查通过后再继续。

## 第一轮：工程初始化与环境连通

- 建立 `frontend/`、`backend/`、`database/`、`docs/`，补充忽略规则和环境配置示例。
- 前端初始化 Vue 3、Vite、TypeScript、Router、Pinia、Axios、Naive UI、Tailwind；后端初始化 FastAPI、SQLAlchemy、Pydantic、PyMySQL、PyJWT、密码哈希及配置读取依赖。
- 后端采用同步 SQLAlchemy 会话，通过请求依赖创建和关闭连接；连接参数从 `.env` 读取。
- 检查本机 MySQL 安装情况；若缺失，先完成环境准备。使用 MySQL 8、`utf8mb4` 和独立开发数据库。
- 提供 `database/init.sql`，初始化数据库；后续第二轮补充用户表。初始化不删除已有数据，不在应用启动时自动重建表。
- 实现 `GET /api/health`，实际检查数据库连通性；正常返回统一成功响应，连接失败返回 HTTP 503。
- 前端开发服务器代理 `/api` 和 `/uploads` 到后端，验证页面能够请求健康检查。
- 从本轮开始维护 README，记录环境要求、数据库配置、前后端启动命令。

**验收：**依赖安装成功，前后端分别启动成功；数据库可连接；浏览器获取健康检查结果；断开数据库后接口正确报告不可用。

## 第二轮：用户系统、认证与公共 API

- 按草稿建立公共层、认证层、用户层及三个业务模块目录。
- 用户表仅包含 `id`、`username`、`password_hash`、`nickname`、`avatar`、`created_at`、`updated_at`；用户名唯一，密码使用 Argon2 哈希。
- 用户名限定 3–32 位字母、数字或下划线，统一转小写；密码 8–128 字符；昵称 1–32 字符，注册未填写时默认使用用户名。用户名注册后不可修改。
- 固定公共接口：

| 接口 | 输入与行为 |
|---|---|
| `POST /api/auth/register` | 用户名、密码、可选昵称；返回公开用户信息 |
| `POST /api/auth/login` | 用户名、密码；返回 `access_token`、`token_type`、`expires_in` |
| `GET /api/users/me` | 获取当前用户信息 |
| `PUT /api/users/me` | 更新昵称和头像 URL，未提交字段保持原值 |

- 注册成功后进入登录页并预填用户名，不自动登录。
- JWT 有效期 24 小时，保存于 `localStorage`；不引入刷新令牌。退出清除本地认证信息，已签发 Token 在到期前仍有效。
- Pinia 仅管理 `token`、`currentUser`，派生 `isAuthenticated`；页面刷新后通过 `/users/me` 恢复并验证身份。
- 统一 Axios 客户端负责地址、10 秒超时、Bearer Token、响应解包和错误提示。认证失效时清空状态，受保护页面跳转登录，登录后返回原站内页面。
- API 使用 `{code, message, data}`；HTTP 状态与 `code` 一致。重复用户名返回 409、认证失败返回 401、参数错误返回 422，服务端异常返回 500且不泄漏内部细节。
- 统一处理校验错误、HTTP 异常及未处理异常；定义分页类型 `{items, total, page, page_size}`，不添加业务分页接口。

**验收：**自动化测试覆盖注册、重复用户名、密码哈希、正确和错误密码登录、匿名访问拒绝、有效及过期 Token、资料获取与更新。使用独立 MySQL 测试库，禁止清理开发数据库。

## 第三轮：公共视觉与页面

- 统一 Design Token：绿色主色 `#18A058`、浅灰绿背景、白色卡片、内容最大宽度 1200px、主要圆角 12px、间距 16/24/32px。
- Naive UI 负责表单、按钮、反馈和组件外观，Tailwind 负责布局；只添加必要的全局样式，不引入第二套组件库。
- 提供 `AppHeader`、`AppContainer`、`ModuleCard`、`EmptyState`、`PageHeader`、`UserAvatar`，共享主题与间距。
- 完成首页、注册、登录和个人中心；首页包含宣传标题、三个模块入口、平台简介及登录状态。
- 实现公开路由 `/`、`/login`、`/register`、`/ride`、`/quest`、`/book`。
- 实现受保护路由 `/profile`、`/ride/mine`、`/quest/mine`、`/book/mine`；提供未知路由的 404 页面。
- 三个模块及“我的内容”仅显示说明与开发中状态。个人中心支持昵称编辑，头像上传在第四轮接通。
- 后端预留模块 Router 和说明文件，约定 `/api/rides/**`、`/api/quests/**`、`/api/books/**`，不创建业务数据表或业务接口。
- 适配桌面、平板和手机；移动端导航可折叠，表单提供标签、校验提示和提交中状态。

**验收：**检查 375px、768px、1440px 下布局及导航；验证公开访问、登录跳转、刷新恢复、退出及昵称更新；执行 `npm run build` 并确保包含 TypeScript 检查。

## 第四轮：上传、交接文档与最终验收

- 实现需登录的 `POST /api/files/upload`，使用 multipart 字段 `file`，返回 `{url}`。
- V1 只支持 JPEG、PNG、WebP，单文件最多 5 MiB；检查实际图片内容、限制读取大小，并生成随机文件名。
- 图片保存至 `backend/uploads/`，通过 `/uploads/` 提供访问，返回相对 URL。用户表仅保存头像 URL，资料更新仅接受本服务有效上传地址或清空头像。
- 个人中心先上传图片，再调用资料更新接口；失败时保留原头像并提示重试。V1 不自动清理未引用文件，文档说明手动维护方式。
- 提供显式运行、可重复执行的开发账号初始化脚本，创建 `user01`、`user02`、`user03`；默认开发密码为 `CampusLink123!`，仅存哈希，不覆盖已有账号。
- 完善 README 与开发约定：安装、数据库初始化、环境变量、启动、测试账号、API 文档、测试命令、模块目录及公共能力使用示例。
- 明确修改公共 User、认证、Layout 和请求工具前需要团队沟通，业务开发者只在各自模块范围扩展。

**验收：**覆盖匿名上传、合法图片、伪造图片、超限文件及头像保存后刷新；完整走通注册→登录→三个占位页→修改昵称和头像→退出→重新登录。后端测试、前端构建通过，并按 README 从新环境验证启动。

## 实施边界与默认约定

- 不实现拼车、悬赏、二手书业务，以及草稿禁止的聊天、支付、积分、后台管理等扩展。
- 实施时确认依赖兼容版本并固定；前端提交锁文件，后端固定依赖版本。
- JWT 密钥由环境配置，拒绝使用示例占位值启动；真实 `.env`、上传文件和运行产物不提交 Git。
- V1 交付本地开发框架，不包含公网部署、生产运维或数据库迁移平台。
- 当前仅制定计划，不修改工程；执行从第一轮开始。
