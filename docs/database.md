# 数据库设计说明书

## 数据存储

使用 MySQL 8，数据库名默认 `campuslink`，字符集 `utf8mb4`，默认排序规则 `utf8mb4_0900_ai_ci`，存储引擎 InnoDB。连接信息从 `backend/.env` 读取。数据库初始化的唯一依据为 [init.sql](../database/init.sql)。

本说明覆盖全系统数据库。当前已实现公共 `user` 表及拼车 `ride_trip`、`ride_member` 表；悬赏与二手书仍预留设计章节。

## 公共用户表

| 字段 | 类型 | 空值 / 默认 | 约束与说明 |
| --- | --- | --- | --- |
| id | BIGINT | 不可空、自增 | 主键，用户唯一标识 |
| username | VARCHAR(32) | 不可空 | 唯一索引 `uq_user_username`，使用 utf8mb4_bin 排序规则 |
| password_hash | VARCHAR(255) | 不可空 | Argon2 密码哈希，不保存明文 |
| nickname | VARCHAR(32) | 不可空 | 页面显示名 |
| avatar | VARCHAR(255) | 可空 | `/uploads/随机文件名.扩展名`，不存图片二进制 |
| created_at | DATETIME(6) | 当前时间 | 创建时间 |
| updated_at | DATETIME(6) | 当前时间，更新时刷新 | 更新时间 |

应用将用户名规范为小写后查询及写入，唯一索引负责并发注册时的最终去重。用户名长度、格式、昵称规则由 Pydantic 校验。头像路径由服务端校验为本站已存在文件，清空时存 NULL。

数据库连接会话设置为 UTC，接口时间输出包含 UTC 时区。通过外部 SQL 工具写入时间数据时也应统一为 UTC。

## 公共关联与设计约定

业务模块通过公共用户主键关联发布者或参与者，不复制密码字段或另建登录表。具体业务表、关系与索引由对应负责人按实际需求设计，并在本文件补充。建议业务表采用可识别的模块命名，避免冲突。

数据库脚本使用 `CREATE ... IF NOT EXISTS`，可重复执行但不负责升级已存在表结构；字段调整应提供明确的增量 SQL，经协调后执行。应用启动不调用自动重建表逻辑。

## 初始化与维护

开发账号由 `python -m app.seed` 显式创建，仅补充缺失账号，不覆盖已有资料。图片位于 `backend/uploads/`，应与数据库共同备份；单独恢复数据库可能造成头像文件缺失。备份、恢复和排障见 [部署维护说明](deployment.md)。

## 业务数据表

### 校园拼车

`ride_trip` 保存发起人、三个地点名称和可空 JSON 地理信息（GCJ-02）、集合说明、UTC 出发时间、招募数、费用、联系方式、备注和行程状态。`ride_member` 保存行程、用户、joined/withdrawn 状态、联系方式与加入/退出时间。招募不含发起人；剩余名额根据有效成员实时统计。

两表均通过外键关联用户，成员表关联行程，并对 `(trip_id, user_id)` 唯一约束；索引覆盖行程状态与时间、发起人、成员用户与状态。加入/退出等操作按行程再成员的顺序加锁，防止并发超额。完整字段、约束见 [建表 SQL](../database/migrations/001_add_ride.sql)，升级方法见 [部署说明](deployment.md)。
