# 校园拼车模块实施计划

本文作为校园拼车的设计与验收依据。业务接口、数据库、页面和高德接入代码已实现；本机业务验证结果见 [测试报告](testing.md)。本机有效 Key 下的地图、搜索、选点及地址解析已验证；浏览器定位仍待用户授权验证，不能将下方验收清单视为全部通过。

## 1. 目标与接入范围

让同学能够围绕相近的出发时间和路线发起同行邀约，完成“发布 → 浏览筛选 → 加入 → 联系同行 → 结束行程”的操作闭环。

采用现有 Vue 3、TypeScript、Naive UI、Tailwind CSS、FastAPI、SQLAlchemy 和 MySQL，新增高德地图 JS API 2.0 作为外部地图服务；密钥代理放在现有 FastAPI 内，不新增运行服务。沿用公共账号、登录守卫、请求工具、响应格式、页面容器和导航。

原 AGENTS.md 将业务模块留给后续负责人；用户已明确要求实现拼车，授权范围扩展到 Ride 的设计和实现。Quest、Book 仍按原有分工保留，公共认证及用户表继续复用。

用户随后明确选择高德地图，地图能力纳入此次 Ride 方案：地点搜索、地图选点、用户主动定位、详情地点展示及手动输入兜底。该要求覆盖原约束中与本模块有关的“不提供地图”限制，其他范围约束继续适用。地图代码已实现，真实 Key 下地图、搜索和选点已通过本机联调；当前位置定位待用户授权验证。

## 2. 产品规则与默认选择

以下是本计划提出的默认方案，不是已有业务事实。为课程项目选择规则清晰、易于演示和交接的实现。

| 项目 | 规则 |
| --- | --- |
| 拼车含义 | 同学自行组织同行，发起人不必是司机；不提供车辆调度、司机认证或实际运力承诺 |
| 人数 | 发起人默认同行；“招募人数”表示除发起人外还需要的同学数量，范围 1–6 人 |
| 加入方式 | 登录后直接加入，每个账号占 1 个名额；不设置申请审批和代人报名 |
| 发起人 | 不占招募名额，不能加入自己发布的行程 |
| 费用 | 可填写每人预计分摊金额，单位元；留空展示“费用协商”，仅作信息说明，实际费用线下协商 |
| 联系方式 | 发布和加入时各填写一种联系方式：微信、QQ 或电话，记录在本次行程中 |
| 地点 | 出发地、目的地、集合地点均支持高德地点搜索、地图选点和主动定位；保留手动输入；不预设学校 |
| 时间 | 面向中国校园，表单与筛选统一采用 Asia/Shanghai，页面标注北京时间；服务端存 UTC |
| 发布期限 | 出发时间必须晚于服务端当前时间，并在未来 90 天内 |
| 编辑 | 仅发起人在未出发、未取消、未完成且当前无人加入时可编辑；有人加入后可取消并重新发布 |
| 退出 | 参与者可在出发前退出，释放名额；退出后在仍可报名时允许重新加入 |
| 取消与完成 | 发起人可在出发前取消；到达出发时间后可标记完成，不自动声称实际出行已完成 |
| 内容保留 | 取消、完成和退出保留历史记录，不提供硬删除入口 |

本模块不增加聊天、支付、评价、积分、管理后台、消息推送或第三方登录；地图负责地点选择、展示与用户指定范围的附近筛选，不增加路线规划、距离计费、导航、自动推荐或实时轨迹。行程状态通过页面查询和操作后刷新体现，不增加轮询或后台定时任务。

## 3. 功能与用户流程

### 3.1 浏览与筛选

- 访客可浏览拼车大厅和行程公开详情。
- 按出发地、目的地、出发日期筛选；手动输入按字面子串匹配；地图选点按对应端点坐标的直线距离筛选，默认 3 公里，可选 1、3、5、10、20 公里。两端选点时必须同时满足，不叠加该端名称条件。
- 大厅只列出尚未出发且未取消的行程，包含满员行程；提供“只看有空位”开关。
- 按出发时间升序、ID 升序稳定排序，每页默认 12 条；换筛选条件回到第一页。
- 筛选和页码写入路由 query，详情返回时保留；输入不立即发请求，点击“查找同行”提交，可一键重置。
- 无行程、无筛选结果、加载中、请求失败分别展示明确状态；失败可重试。

### 3.2 发布与编辑

1. 点击“发布拼车”；未登录先登录，再返回发布页。
2. 通过地点搜索、地图选点或手动输入填写路线及集合地点；填写时间、招募人数、联系方式；预计费用和备注可选。地图选点须显式确认，不把定位结果自动作为发布地点。
3. 前端检查必填及格式，服务端再次校验，以服务端时间为准。
4. 提交时禁用重复点击；成功后进入详情，提示“拼车已发布”。
5. 发布失败保留表单；离开有改动的表单时询问是否放弃。
6. 编辑使用同一表单，只加载本人有权编辑的行程；提交时后端重新确认无人加入。

### 3.3 加入、退出与联系

1. 详情展示路线、时间、集合点、当前剩余名额、预计费用、备注和发起人昵称/头像。
2. 访客看到“登录后加入”；登录返回当前详情。
3. 可报名时点击“加入拼车”，弹窗填写本人联系方式，说明该信息将提供给发起人。
4. 提交后占用 1 个名额；页面展示“已加入”和退出入口，同时允许查看发起人联系方式。
5. 参与者退出前确认，成功后释放名额，并失去查看发起人联系方式的权限。
6. 重复加入不增加人数；满员、已出发、已取消等情况明确说明并刷新行程。
7. 发起人在自己的行程详情中查看当前参与者昵称、头像及联系方式；参与者彼此不展示联系方式。

### 3.4 我的拼车

- `/ride/mine` 保留原入口，分为“我发布的”“我参与的”两个页签，各自分页。
- 我发布的：展示所有本人行程，可查看详情；按状态显示编辑、取消或完成按钮。
- 我参与的：包含当前参与和已退出记录，分别显示行程状态与“已加入 / 已退出”，避免混为一个状态。
- 默认按创建时间倒序、ID 倒序排列；重新加入更新原参与记录，不复制历史条目。
- 取消行程后仍在参与者历史中显示“已取消”，不占用其他行程名额，也不伪造退出动作。
- 取消和完成操作均有确认提示；取消提示包含“参与者将不能继续加入该行程”。

## 4. 页面与视觉设计

### 地图相关用户流程

三个地点字段共用一个地点选择器，每次弹窗只编辑一个字段，弹窗内修改先保留为草稿；点击“确认地点”才回填，取消不修改表单。

| 字段 | 初始地图视野 | 选择方式与补充 |
| --- | --- | --- |
| 出发地 | 优先已选坐标，否则用户选择的城市或全国视野 | 输入学校/站点名称，查看名称及城市地址后选择；支持地图点击、拖动标记或主动定位 |
| 目的地 | 优先已选坐标，否则出发地附近；可切换搜索城市 | 支持跨城搜索，不能强制锁定在出发地城市；也可地图选点或主动定位 |
| 集合地点 | 优先已选集合坐标，否则出发地坐标 | 在出发地附近选校门/站台等具体点；可补充“右侧便利店门口”等集合说明 |

地图搜索采用输入建议和 POI 查询。建议项若没有坐标，必须查询具体地点或让用户在地图确认，不能把“城市/类别建议”当作有效坐标保存。城市选择只作为当前查询条件，不增加独立城市数据库。

地图点击或拖动标记后，使用逆地理编码获取地址；地址获取失败时保留选点，允许用户填写名称及地址后确认。自动解析到的街道地址只能作为参考，不自动认定为准确校门。

点击“使用当前位置”前显示简短说明：浏览器及高德将用于获取当前位置，位置仅用于本次选点。用户触发后再请求权限，不在页面打开时主动定位，不持续跟踪，也不建立用户定位历史。定位成功后展示候选点供确认；拒绝、超时或不可用时提供搜索和手动选择。

修改已选地点的名称时，清空该字段附带的坐标、地址和 POI 信息并转为手动输入，避免“新名称配旧坐标”。修改集合补充说明不清空集合坐标。更换出发地不自动覆盖集合地点，应提示用户重新确认集合点。

大厅支持明确选择地图位置后按距离筛选；没有对应坐标的行程不纳入距离结果，可清除选点改用名称查找。卡片显示距选点的直线距离，仍按出发时间、ID 排序。详情地图只展示有坐标的出发地、目的地和集合点，并自动调整视野；不画容易误认为实际道路路线的连接线。无坐标的地点正常显示文字，不生成猜测坐标。

发布前明确显示“发布后，所选行程地点将对其他用户可见”。只有确认发布的地点进入数据库；浏览地图、搜索或定位产生的临时结果不写入项目数据库。对接高德仅发送所需的搜索词/地点信息，不发送 CampusLink Token、联系人或个人资料。

### 4.3 地图弹窗与降级显示

- 地点框右侧增加“地图选点”；已选地点下方显示详细地址，集合点下方提供独立补充说明输入框。
- 弹窗使用 NModal、现有主题及绿色确认按钮，桌面宽度约 860px，地图高约 360px；手机弹窗接近全屏，搜索结果与地图纵向排列，底部操作始终可访问。
- 明确保留高德标识和版权信息；不覆盖地图来源标记。外框、表单及操作区跟随本站风格，地图标注同时显示“起点 / 终点 / 集合”文字。
- 只在用户打开选点弹窗或详情中点击“查看地图”时加载 SDK；大厅卡片不加载地图实例。
- 关闭弹窗/离开详情时销毁地图实例、解绑事件； SDK 加载使用共享 Promise，失败后可显式重试。
- 搜索输入约 300ms 防抖，空输入不查询；使用请求序号丢弃旧搜索和旧逆编码结果，防止快速选点时被过期响应覆盖。
- SDK 加载、搜索、定位均设置有限超时；不无限重试。关闭弹窗后到达的回调不能再回填表单。
- 未配置 Key、额度不足、网络异常或定位拒绝时，提示“地图暂不可用，可手动填写地点”，继续允许发布和编辑；技术排障原因只进入脱敏日志及开发文档。
- 自动化验收中断网兜底成功不等于地图接入成功，真实搜索/选点/定位另行记录结果。

## 5. 状态与权限

### 5.1 状态定义

数据库行程状态只存 `scheduled`（已发布）、`cancelled`（已取消）、`completed`（已完成）。满员与已到出发时间由当前人数和时间推导，避免依赖定时写库。

| 显示状态 | 条件，按表内优先级判断 | 可执行操作 |
| --- | --- | --- |
| 已取消 | status = cancelled | 仅查看 |
| 已完成 | status = completed | 仅查看 |
| 已到出发时间 | scheduled 且 departure_at <= 服务端当前时间 | 发起人可标记完成；不再加入、退出或编辑 |
| 已满员 | scheduled、未出发且 joined_count = recruit_seats | 当前参与者可退出；发起人可取消 |
| 可报名 | scheduled、未出发且 joined_count < recruit_seats | 其他用户可加入，参与者可退出，发起人可取消；无人加入时可编辑 |

状态转换：`scheduled → cancelled` 仅出发前；`scheduled → completed` 仅到达出发时间后。取消与完成不可撤销，需确认。完成仅表示发起人结束本条邀约，不证明实际运送或支付情况。

参与记录状态只存 `joined`、`withdrawn`；允许 `joined → withdrawn → joined`，每次均重新校验行程条件。一个用户同一行程始终只有一条记录，不设计审计事件表。

### 5.2 可见性与归属校验

- 公开列表与详情仅返回公开资料；响应中绝不夹带联系方式或完整参与者列表。
- 独立受保护接口返回“我与本行程的关系”，不要让公开接口解析可选 Token 后混合返回私密数据。
- 当前参与者及发起人可查看发起人联系方式；发起人可查看当前参与者列表及联系方式。
- 退出后不再返回双方联系方式；取消后不再提供联系接口。已完成或到达出发时间的行程，仍按原参与关系授权，便于线下收尾。
- 联系信息只保存在 Ride 表内，不扩展公共 user 表；详情接口返回的可操作标记仅辅助 UI，写接口必须独立校验。
- 私密响应设置 `Cache-Control: no-store`；前端退出登录、退出行程或切换行程时清空联系信息。
- 发起人 ID、参与者 ID 均取 CurrentUser，客户端不得指定 owner_id 或 user_id；其他用户不能编辑、取消、完成他人的行程。

## 6. 数据库设计

新增 `ride_trip` 和 `ride_member` 两张表，使用 InnoDB、utf8mb4，主外键类型与现有 user.id 一致。时间采用 DATETIME(6)，统一存 UTC，接口带时区输出。

### 6.1 ride_trip：行程

| 字段 | 类型 | 空值 / 默认 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT | 主键、自增 | 行程 ID |
| owner_id | BIGINT | 非空 | 外键 user.id，发起人 |
| origin | VARCHAR(80) | 非空 | 出发地，去首尾空格后 2–80 字符 |
| destination | VARCHAR(80) | 非空 | 目的地，2–80 字符；完整地点信息不得与出发地相同，同名但不同城市或不同点可区分 |
| meeting_point | VARCHAR(160) | 非空 | 集合地点，2–160 字符 |
| origin_location | JSON | 可空 | 出发地结构化信息，格式见下文 |
| destination_location | JSON | 可空 | 目的地结构化信息，格式同上 |
| meeting_location | JSON | 可空 | 集合地点结构化信息，格式同上 |
| meeting_note | VARCHAR(200) | 非空 / 空串 | 集合补充说明，不替代地点名称或地址 |
| departure_at | DATETIME(6) | 非空 | 出发时间 |
| recruit_seats | SMALLINT | 非空 | 招募人数 1–6，不含发起人 |
| estimated_cost | DECIMAL(8,2) | 可空 | 每人预计费用 0–9999.99；不使用浮点数存储 |
| contact_type | VARCHAR(16) | 非空 | wechat / qq / phone |
| contact_value | VARCHAR(64) | 非空 | 3–64 字符，去首尾空格；禁止换行及控制字符 |
| note | VARCHAR(500) | 非空 / 空串 | 可选备注，最长 500 字符 |
| status | VARCHAR(16) | 非空 / scheduled | 行程持久化状态 |
| created_at | DATETIME(6) | 当前 UTC 时间 | 创建时间 |
| updated_at | DATETIME(6) | 更新时刷新 | 更新时间 |

索引：`(status, departure_at, id)` 支持大厅时间筛选，`(owner_id, created_at, id)` 支持本人列表。子串地点搜索不承诺命中普通索引，课程规模下不增加全文检索服务。

三个 location 字段结构固定为 `{address, longitude, latitude, poi_id, adcode, source, coordinate_system}`，由嵌套 Pydantic 模型严格校验，多余字段拒绝。选择 JSON 是因为本期不做坐标距离检索，不增加空间索引；SQL NULL 表示手动地点，无需地图也能保存。

| 属性 | 类型与限制 | 说明 |
| --- | --- | --- |
| address | string，0–300 字符 | 地点详细地址，逆编码失败时允许补填或为空 |
| longitude / latitude | 成对有限数值 | 经度 -180–180、纬度 -90–90，统一保留至 6 位小数；拒绝 NaN、Infinity、缺一项 |
| poi_id | string 或 null，最长 64 | 搜索具体 POI 后有值；点击地图/定位选点可为空 |
| adcode | 6 位数字字符串或 null | 行政区划代码，未知时为空，不伪造 |
| source | poi / map / geolocation | 用户确认地点的来源，仅作来源说明，不证明身份或位置真实性 |
| coordinate_system | 固定 gcj02 | 统一采用高德坐标体系，禁止混存 WGS84 或 BD09 |

不把浏览器原始 GPS 坐标直接当高德坐标。优先使用高德插件返回的已转换坐标；接入时核对插件输出与配置，原始坐标必须通过官方转换能力处理，不能重复转换。相同起终点校验：双方有坐标时，规范化后相同坐标拒绝；任一无坐标时，规范化的名称和地址组合相同则拒绝。不仅以名称相同就拒绝跨城同名地点。

地点仅是用户提供的出行信息，后端做类型与范围校验，不把客户端的 POI ID 或 source 当作可信定位证明。每次发布不额外请求高德核验，以免地图服务故障阻断正常业务。

### 6.2 ride_member：参与关系

| 字段 | 类型 | 空值 / 默认 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT | 主键、自增 | 参与记录 ID |
| trip_id | BIGINT | 非空 | 外键 ride_trip.id |
| user_id | BIGINT | 非空 | 外键 user.id |
| status | VARCHAR(16) | 非空 / joined | joined / withdrawn |
| contact_type | VARCHAR(16) | 非空 | 同上 |
| contact_value | VARCHAR(64) | 非空 | 仅发起人可见的参与者联系方式 |
| created_at | DATETIME(6) | 当前 UTC 时间 | 首次参与时间 |
| updated_at | DATETIME(6) | 更新时刷新 | 退出或重新加入时间 |

唯一约束 `(trip_id, user_id)` 防止重复参与；索引 `(trip_id, status)` 用于人数统计，`(user_id, created_at, id)` 用于参与历史。外键删除采用 RESTRICT，不级联删除用户或历史行程。

数据库 CHECK 与 Pydantic 共同约束人数、费用和枚举状态；跨表归属与时间规则由服务层校验。报名人数从 joined 记录统计，剩余名额等于招募人数减已加入人数，不额外维护容易失配的冗余计数。

## 7. 接口设计

前缀统一 `/api/rides`。复用 CurrentUser、DatabaseSession、ApiResponse 和 PageData；成功 HTTP 200，响应 `{code,message,data}`。以下为计划契约，最终同步到 FastAPI `/docs`。

| 方法与路径 | 登录 | 请求 / 返回 data |
| --- | --- | --- |
| GET `/api/rides` | 否 | origin、destination、departure_date、available_only、page、page_size，以及可选成对 origin_lng/origin_lat、destination_lng/destination_lat 和 radius_km（0.5–20，默认 3）；返回分页 RideSummary，选点时包含对应 origin_distance_km / destination_distance_km |
| POST `/api/rides` | 是 | 行程表单；返回公开 RideDetail |
| GET `/api/rides/mine` | 是 | scope=published/participating、page、page_size；返回分页 MineRideItem |
| GET `/api/rides/{id}` | 否 | 返回公开 RideDetail，包含取消/完成的行程 |
| PUT `/api/rides/{id}` | 是，本人 | 完整可编辑表单；返回更新后的 RideDetail |
| POST `/api/rides/{id}/join` | 是，非本人 | contact_type、contact_value；返回 MembershipResult |
| POST `/api/rides/{id}/leave` | 是，参与者 | 空请求体；返回 MembershipResult |
| POST `/api/rides/{id}/cancel` | 是，本人 | 空请求体；返回 RideDetail |
| POST `/api/rides/{id}/complete` | 是，本人 | 空请求体；返回 RideDetail |
| GET `/api/rides/{id}/membership` | 是 | 返回本人角色、参与状态、允许操作，不含其他人的联系方式 |
| GET `/api/rides/{id}/contacts` | 是，按关系授权 | 返回授权可见的联系方式；发起人额外看到当前参与者 |

先注册 `/mine` 静态路径，再注册动态 ID 路径。分页默认 12、最大 50，仍用公共 PageData 包装；负数、未知枚举、非法时间及多余写入字段返回 422。

### 7.1 响应对象

- `RideSummary`：id、origin、destination、meeting_point、departure_at、recruit_seats、joined_count、remaining_seats、estimated_cost、status、display_status、owner（仅 id/nickname/avatar）、created_at。
- `RideDetail`：在 Summary 上增加 note、updated_at、server_time、origin_location、destination_location、meeting_location、meeting_note；不含 contact_type/contact_value。费用以十进制定点字符串或 null 输出。公开地点与坐标可见性在发布前告知；列表不返回坐标 JSON 以控制响应体大小。
- `MineRideItem`：Summary，加本人 member_status（发起列表为空）及参与记录时间；无联系方式。
- `MembershipResult`：trip_id、role（owner/member/visitor）、member_status（joined/withdrawn/null）、can_join、can_leave、can_edit、can_cancel、can_complete；这里 visitor 指已登录但未参与本行程。
- `Contacts`：owner 联系对象，以及仅发起人收到的 active_members 数组；联系人公开身份只包含 id/nickname/avatar。

创建请求示例（日期仅为示例，提交时必须满足未来时间规则）：

```json
{
  "origin": "学校南门",
  "destination": "高铁站",
  "meeting_point": "南门公交站旁",
  "origin_location": null,
  "destination_location": null,
  "meeting_location": null,
  "meeting_note": "右侧便利店门口",
  "departure_at": "2026-09-25T14:30:00+08:00",
  "recruit_seats": 3,
  "estimated_cost": "25.00",
  "contact_type": "wechat",
  "contact_value": "campus_demo",
  "note": "每人带一件小行李，请提前五分钟集合。"
}
```

日期筛选按北京时间某日的 `[00:00, 次日00:00)` 转成 UTC 查询；写入不接受无时区时间。前端不能简单拼接本机时区或依赖浏览器所在时区解释日期。

以上示例为手动填写地点的合法请求。地图选点时把对应 null 替换为符合地点模型的对象；三个字段可分别使用不同输入方式，不要求全部有坐标。

### 7.2 异常处理

| HTTP | 场景 | 页面处理 |
| --- | --- | --- |
| 401 | 未登录、登录过期 | 复用现有认证处理，返回登录页并保留站内目标 |
| 403 | 非本人管理、无权查看联系方式、发起人加入自己行程 | 显示无权执行，隐藏失效操作 |
| 404 | 行程不存在 | 展示找不到行程，返回大厅 |
| 409 | 已满员、已出发、不可编辑或状态冲突 | 展示具体原因并重新加载详情 |
| 422 | 参数不合法 | 显示校验信息并保留输入 |
| 500 / 网络失败 | 保存失败、连接失败 | 保留表单，解除 loading，允许重试 |

复用统一请求的错误提示；页面需要表单内反馈时传 `silent: true`，避免重复弹出相同错误。不通过放宽公共异常处理来绕过业务错误。

### 7.3 高德接入与本地配置

采用高德 JS API 2.0，使用 AutoComplete、PlaceSearch、Geocoder、Geolocation 与地图 Marker。只引入官方 `@amap/amap-jsapi-loader` 作为必要加载依赖，具体兼容版本在实施时核对并锁定。无需另建地图服务或申请 Web 服务 Key 来重复实现同一套 POI 搜索。

| 配置 | 存放位置 | 用途 |
| --- | --- | --- |
| VITE_AMAP_KEY | frontend/.env.local | Web 端 JS API Key；这是浏览器可见标识，不宣称可以隐藏 |
| AMAP_SECURITY_CODE | backend/.env | JS API 安全密钥，后端 SecretStr 字段，不带 VITE_ 前缀 |
| VITE_AMAP_SERVICE_HOST | frontend/.env.local，默认 /_AMapService | SDK 安全代理地址，与 Vite 开发代理和正式部署保持一致 |

后端安全密钥是可选配置，未填写时核心业务仍能启动。前端无 Key 时直接使用手动输入；仅有 Key 但代理缺少安全密钥时返回地图不可用，不暴露配置内容。

请求路径：浏览器加载 SDK → SDK 使用 serviceHost → Vite 将 `/_AMapService` 转给 FastAPI → FastAPI 向固定高德上游转发并注入安全密钥。设置 `_AMapSecurityConfig.serviceHost` 必须早于 SDK 初始化。代理按官方文档确定的服务路径显式允许，禁止任意上游 URL、任意主机或用户覆盖 jscode，不转发本站 Authorization/Cookie，不在日志记录完整查询参数或密钥；限制请求方法、长度、超时及响应大小。允许的路径最终以官方协议与插件实际请求核对后落地，不能把通用透传代理直接暴露出去。

代理遵循高德 SDK 原生响应协议，不套 ApiResponse；它是基础设施代理，不是 Ride 业务 JSON 接口。上游失败和无配置时返回适合 SDK 识别的失败 HTTP 状态，前端地图区域显示降级提示。应用请求仍走公共 request，SDK 请求走其专用代理，二者不混用。

新增配置的说明写入 .env.example；真实 Key 与安全密钥只写入本机被 Git 忽略的环境文件。开发时检查 Key 类型、账号服务权限和来源限制；额度及是否需要付费以用户高德控制台当前显示为准，不承诺永久免费或自动购买服务。

后续真实地图联调需要用户在自己的高德账号创建应用和 Web 端（JS API）Key/安全密钥，并写入上述本机环境文件，无需把密钥发到聊天。没有 Key 时可以完成核心业务、地图组件及降级处理，但不得把地图功能标记为联调通过。

定位验收使用本机 `http://127.0.0.1:5173`，记录浏览器支持与权限结果；手机通过局域网 HTTP 地址访问不能直接等同于本机回环地址，定位需另行在受信任 HTTPS 环境验证。正式部署提供 HTTPS，不通过关闭浏览器安全设置绕过限制。定位拒绝/设备无定位能力时，地图搜索选点仍应可用。

相关技术依据来自高德官方文档，核对日期为 2026-09-21：

- [输入提示与 POI 搜索](https://developer.amap.com/api/javascript-api-v2/guide/services/autocomplete)：名称搜索与候选地点。
- [地理编码与逆地理编码](https://developer.amap.com/api/javascript-api-v2/guide/services/geocoder)：选点后解析地址。
- [定位](https://developer.amap.com/api/javascript-api-v2/guide/services/geolocation)：Geolocation 及 HTTPS 限制。
- [安全密钥使用](https://developer.amap.com/api/javascript-api-v2/guide/abc/jscode)：安全密钥通过服务器代理使用。

## 8. 并发与数据一致性

所有影响名额或行程状态的写操作，包括编辑、加入、退出、取消、完成，统一先通过 `SELECT ... FOR UPDATE` 锁定同一行程行，再读参与关系、判断规则、写入并提交。固定“行程 → 参与记录”的锁顺序。

加入的事务顺序：锁定行程 → 校验状态和服务端时间 → 排除发起人 → 检查已有参与记录 → 统计 joined 人数 → 校验剩余名额 → 新建或恢复参与关系 → 提交。并发事务等待同一行程锁，第二个请求拿锁后必须重算人数，不能复用列表展示的余位。

为防止 MySQL 可重复读下旧快照影响判断，事务在认证读取之后，对参与记录采用当前读/锁定读取，或明确建立适合该业务事务的读取边界；不能只锁行程后用可能过期的快照统计人数。实施时以双用户抢最后名额的实际结果验证。

- 当前仍为 joined 的重复 join 返回现有参与结果，不新增、计数或偷偷修改联系方式；终态行程依然拒绝新的状态变化。
- 已 withdrawn 的重复 leave 返回当前结果，不重复释放名额；没有参与记录返回 409。
- 本人重复 cancel/complete 在已经是相同终态时返回当前结果；不同终态之间转换返回 409。
- 创建行程以提交期间禁用按钮防止普通重复点击，不增加全局幂等键系统；网络中断且不确定是否发布成功时提示先查看“我发布的”。
- 写入异常回滚，不留部分更新；前端操作成功后重查详情和本人关系，已加载的联系人同步清空或刷新。
- 公开列表查询按页聚合参与人数和发起人信息，避免每个卡片单独查询一次数据库。
- 页面停留跨过出发时间时按 server_time 计算时差并更新按钮；最后以写接口检查结果为准。

## 12. 交付标准

最终应交付可运行的拼车模块、两张表的初始化及升级 SQL、与原站一致的五个页面入口，以及更新后的模块说明和全组相关文档。在当前电脑上能通过现有启动入口运行，并实际走通：user01 发布 → user02 加入 → 双方按权限查看联系信息 → 退出或取消 → 查看历史；另行验证到时完成流程。

地图交付须额外满足：真实 Key 联通高德搜索及选点，主动定位有实测结果或明确设备限制，地点坐标随发布保存并在详情正确回显；无 Key 和网络故障时仍能手动填写完成业务。核心拼车和地图联调分别报告，不用其中一项通过代替另一项。

计划文档本身本次即交付；数据库迁移、页面及 API 实现留到后续开发步骤执行。
