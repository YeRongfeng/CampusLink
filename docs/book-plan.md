# 校园二手书模块设计说明

本文记录二手书模块的设计与验收依据，风格与内容深度参照 [拼车计划](ride-plan.md)。业务接口、数据库、页面已实现；实际验证结果见 [测试报告](testing.md)。

## 1. 目标与场景

同学之间有大量用过一两学期就闲置的教材、教辅和复习资料，本模块让这些书能够继续被使用，而不是直接当废纸处理。核心流程是“发布 → 浏览筛选 → 收藏/联系卖家 → 线下交易 → 标记完成”。

不做自建交易担保、在线支付、物流跟踪、议价聊天室或书籍条码库存比对；价格、议价、交付方式均由买卖双方线下确认，系统只负责信息展示、检索和权限控制。沿用公共账号、登录守卫、请求工具、响应格式、页面容器和导航，不新建一套用户体系。

## 2. 产品规则与默认选择

| 项目 | 规则 |
| --- | --- |
| 发布主体 | 任意登录用户均可发布书籍，不需要先前成交记录或认证 |
| 分类 | 教材、教辅、考试资料、文学读物、其他五类，发布时必选 |
| 成色 | 全新、几乎全新、轻微使用痕迹、明显使用痕迹四级，发布时必选，由卖家自行判断 |
| 图片 | 至少 1 张、最多 6 张，第一张作为封面；图片仅能引用本站已上传的文件 |
| 价格 | 现价必填，0–9999.99 元；原价可选，若填写不能低于现价，用于计算折扣展示；是否可议价由卖家勾选 |
| 交易方式 | 当面交易、校内代送、均可协商三选一；交易地点为必填文字说明 |
| 联系方式 | 发布时填写微信、QQ 或电话，仅在书籍在售或已预定时对非卖家开放 |
| 状态 | 在售、已预定、已售出、已下架四态；已预定仅作提示用途，不锁定给特定买家、不限制其他人继续联系卖家 |
| 收藏 | 登录用户可收藏他人发布的书籍，不能收藏自己发布的书籍；收藏用于个人整理，不触发通知 |
| 编辑 | 仅发布者在书籍仍为“在售”状态时可编辑；已预定、已售出或已下架后只能下架或保留记录，不能继续修改详情 |
| 内容保留 | 下架、售出保留历史记录在“我发布的”中，不提供硬删除入口 |

不增加聊天、支付、评价、积分、管理后台、消息推送或第三方登录；不做跨校区地图选点，交易地点仅为文字描述。浏览次数和收藏数仅做展示，不作为排序以外的业务判断依据。

## 3. 功能与用户流程

### 3.1 浏览与筛选

- 访客可浏览书摊和书籍公开详情，不需要登录。
- 支持书名/作者关键词、分类、成色、交易方式、价格区间、是否可议价、是否仅看在售的组合筛选；关键词按子串匹配书名或作者。
- 默认按发布时间倒序排列，可切换价格从低到高或从高到低；每页 12 条。
- 书摊默认同时展示在售和已预定的书籍，“仅看在售”可进一步排除已预定；已售出和已下架的书籍不出现在书摊，但仍可通过已获得的链接直接访问详情（用于历史记录追溯）。
- 筛选条件写入路由 query，切换分页、返回书摊时保留；提供“重置”一键清空。

### 3.2 发布与编辑

1. 点击“发布书籍”，未登录先登录，再返回发布页。
2. 依次填写书名、作者、ISBN（选填）、分类、成色、描述、图片、价格、交易方式、交易地点和联系方式。
3. 图片通过公共上传接口逐张上传，上传后在表单内可调整封面（默认第一张）和删除；最终提交时后端会重新校验图片确实来自本站上传目录。
4. 前端校验必填项和格式，后端再次校验，拒绝原价低于现价、空图片列表等不合理组合。
5. 提交成功后进入详情页并提示“书籍已保存”；离开有改动的表单时询问是否放弃。
6. 编辑复用发布表单，只加载本人发布且仍在售的书籍；提交时后端重新确认编辑条件，书籍已被预定或下架后拒绝编辑。

### 3.3 收藏与联系卖家

1. 详情页展示全部图片、分类、成色、价格（含原价折扣角标）、描述、交易方式和地点。
2. 登录用户可对他人发布的在售或已预定书籍点击收藏，再次点击取消收藏；收藏状态和收藏总数实时展示。
3. 有意向的同学点击“查看联系方式”获取卖家的联系方式，用于线下进一步沟通和验货；联系方式在书籍已售出或已下架后不再对非卖家开放。
4. 卖家在自己的详情页可以直接看到联系方式（用于核对发布信息），并看到编辑、标记预定/取消预定、标记售出、下架等管理操作。

### 3.4 我的书籍

- `/book/mine` 分为“我发布的”“我收藏的”两个页签，各自分页，默认按时间倒序。
- 我发布的：展示全部状态的书籍，可查看详情；按状态显示编辑、预定、取消预定、标记售出、下架等可执行操作。
- 我收藏的：展示当前仍然有效的收藏记录及收藏时间；书籍被卖家下架或售出后仍保留收藏记录用于查看历史，但联系方式不再可见。
- 下架、售出操作均有二次确认提示，说明操作不可撤销。

## 4. 页面与视觉设计

沿用与校园拼车一致的视觉约定：绿色主色、白色卡片、12px 圆角、AppContainer/AppHeader/PageHeader 公共布局，业务卡片单独建立 BookCard，不改造公共 ModuleCard。

| 路由 | 页面 | 权限 | 主要内容 |
| --- | --- | --- | --- |
| `/book` | 书摊 | 公开 | 标题、发布/我的入口、筛选条、书籍卡片、分页 |
| `/book/new` | 发布书籍 | 登录 | 分组表单：书籍信息、价格、交易方式与联系方式 |
| `/book/:id` | 书籍详情 | 公开，联系方式按权限加载 | 图片画廊、价格、描述、卖家信息、收藏与管理操作 |
| `/book/:id/edit` | 编辑书籍 | 登录且本人发布 | 复用发布表单，提交时重新校验编辑条件 |
| `/book/mine` | 我的书籍 | 登录 | 我发布的、我收藏的及对应状态操作 |

注册静态路由时区分 `new`、`mine` 与动态 ID，与拼车模块保持相同的路由顺序约定。书籍卡片展示封面图、分类/成色标签、折扣角标（如有原价）、价格、收藏数和浏览次数；详情页左侧为图片与书籍信息，右侧为卖家信息、操作区和联系方式区，手机端改为纵向堆叠。

## 5. 状态与权限

### 5.1 状态定义

数据库状态只存 `listed`（在售）、`reserved`（已预定）、`sold`（已售出）、`removed`（已下架），不单独维护浏览次数以外的派生状态。

| 状态 | 条件 | 可执行操作 |
| --- | --- | --- |
| 在售 listed | 默认发布状态 | 非卖家可收藏、查看联系方式；卖家可编辑、标记预定、标记售出、下架 |
| 已预定 reserved | 卖家主动标记 | 非卖家仍可收藏、查看联系方式；卖家可取消预定（回到在售）、标记售出、下架；不可编辑 |
| 已售出 sold | 卖家标记，终态 | 仅查看，非卖家不再查看联系方式；不可恢复 |
| 已下架 removed | 卖家下架，终态 | 仅查看，非卖家不再查看联系方式；不可恢复 |

状态转换：`listed ⇄ reserved`、`listed/reserved → sold`、`listed/reserved → removed`；`sold`、`removed` 均为终态。重复提交相同目标状态的操作返回当前结果而不是报错，便于前端网络重试；终态之间或终态回退到非终态均拒绝。

### 5.2 可见性与归属校验

- 公开列表与详情仅返回公开资料，不包含联系方式；联系方式通过独立接口在权限允许时才返回。
- 卖家可随时查看自己发布书籍的联系方式（用于编辑回显和核对），非卖家仅在书籍处于在售或已预定时可查看。
- 卖家不能收藏自己发布的书籍；收藏、取消收藏、编辑、状态变更均在后端重新校验归属，不仅依赖前端按钮的显示与隐藏。
- 私密响应（我的书籍、联系方式、关系信息）设置 `Cache-Control: no-store`。

## 6. 数据库设计

新增 `book_listing` 和 `book_favorite` 两张表，使用 InnoDB、utf8mb4，主外键类型与现有 `user.id` 一致，时间统一存 UTC。详细字段说明见 [数据库设计说明书](database.md)，完整字段、约束见 [建表 SQL](../database/migrations/002_add_book.sql)。

设计要点：
- 封面图片以 JSON 数组形式保存在 `book_listing.cover_images` 中，数组首项为封面；校验由 Pydantic 在写入前完成（长度 1–6、每项必须是本站已存在的上传文件），不在数据库层做 JSON 结构 CHECK，与现有 Ride 模块对 JSON 列的处理方式一致。
- 价格使用 `NUMERIC(8,2)` 定点存储，并通过 CHECK 约束保证原价不低于现价、价格落在 0–9999.99 区间，避免浮点误差。
- 收藏关系使用独立表并建立 `(listing_id, user_id)` 唯一约束，防止重复收藏；并发收藏时依赖数据库唯一约束而非应用层判断来保证最终一致，已通过并发请求实测验证。
- 浏览次数 `view_count` 采用数据库原子自增（`UPDATE ... SET view_count = view_count + 1`），避免高并发下的读-改-写竞态造成计数丢失。
- 索引覆盖书摊的状态/分类/时间组合查询和个人发布记录查询，命名与现有 Ride 模块的索引命名风格保持一致。

### 6.1 现有数据库升级

- 新安装：`database/init.sql` 已在拼车表之后加入两张二手书表。
- 已安装：执行 `database/migrate_book.py`（用法与 `migrate_ride.py` 一致），仅创建缺失的两张表，不清空用户或其他业务数据，可重复执行。
- 不删除或重建 campuslink 数据库，不修改现有账号、密钥、头像及拼车、悬赏模块数据。

## 7. 接口设计

前缀统一 `/api/books`。复用 `CurrentUser`、`DatabaseSession`、`ApiResponse` 和 `PageData`；成功 HTTP 200，响应 `{code,message,data}`。接口契约已同步到运行服务的 `/docs`。

| 方法与路径 | 登录 | 说明 |
| --- | --- | --- |
| GET `/api/books` | 否 | 关键词、分类、成色、交易方式、价格区间、是否可议价、仅看在售、排序、分页；返回分页 BookSummary |
| POST `/api/books` | 是 | 提交完整书籍信息；返回 BookDetail |
| GET `/api/books/mine` | 是 | scope=selling/favorites、分页；返回分页 MineBookItem |
| GET `/api/books/{id}` | 否 | 返回 BookDetail，同时记录一次浏览 |
| PUT `/api/books/{id}` | 是，本人 | 完整可编辑表单，仅在售状态可提交；返回更新后的 BookDetail |
| GET `/api/books/{id}/relation` | 是 | 返回本人与该书籍的关系（是否发布者、是否收藏、可执行操作） |
| GET `/api/books/{id}/contact` | 是，按关系授权 | 返回卖家联系方式 |
| POST / DELETE `/api/books/{id}/favorite` | 是，非本人 | 收藏/取消收藏，返回收藏状态和总数 |
| POST `/api/books/{id}/reserve` 等 | 是，本人 | 预定/取消预定/标记售出/下架，返回更新后的 BookDetail |

先注册 `/mine` 静态路径，再注册动态 ID 路径，与拼车模块保持一致。分页默认 12、最大 50；负数、未知枚举及多余写入字段返回 422。

### 7.1 异常处理

| HTTP | 场景 | 页面处理 |
| --- | --- | --- |
| 401 | 未登录、登录过期 | 复用现有认证处理，返回登录页并保留站内目标 |
| 403 | 非本人管理、无权查看联系方式、收藏自己发布的书籍 | 显示无权执行，隐藏失效操作 |
| 404 | 书籍不存在 | 展示找不到书籍，返回书摊 |
| 409 | 状态不支持当前操作（如已售出书籍再次编辑） | 展示具体原因并重新加载详情 |
| 422 | 参数不合法（价格、图片数量、原价低于现价等） | 显示校验信息并保留输入 |

## 8. 并发与数据一致性

状态变更（编辑、预定、取消预定、售出、下架）统一先通过 `SELECT ... FOR UPDATE` 锁定书籍行，再校验状态并写入提交，锁获取顺序与书籍单表范围一致，不涉及跨表加锁顺序问题。

收藏操作不依赖行锁，而是依赖 `(listing_id, user_id)` 唯一约束：并发重复收藏请求中，后到达的请求遇到 `IntegrityError` 后直接按“已收藏”处理并返回当前结果，不抛出 500 错误；已通过 8 个并发收藏请求的实测验证，最终收藏数稳定为 1。浏览计数使用数据库原子自增语句，不需要加锁。

写入异常回滚，不留部分更新；前端操作成功后重新拉取详情与关系，避免界面停留在旧状态。
